# Minimum Gremlins test efficacy per package, in percent. Read by
# hack/mutation.sh, which fails a package scoring below its entry.
#
# Each entry is the measured score floored to a whole percent and reduced by 3.
# That margin is the tool's measured reproducibility, not padding: efficacy is
# killed/(killed+lived), and a mutant that merely runs slowly is recorded as
# TIMED OUT, leaving the numerator without leaving the denominator, so the score
# moves with machine load. internal/hub scored 92.93 / 90.54 / 89.71 across
# three runs of identical source. A baseline set to the best of those fails on
# any differently loaded machine, and a flaky gate teaches people to ignore it.
#
# Where a package sits below 100 the reason is recorded beside it. An
# equivalent mutant -- one that changes the source without changing anything a
# test could observe -- is a legitimate reason to stop. A test written to
# satisfy the tool rather than to describe the software is not.
#
# The dominant equivalence class here: widening a boundary by one lands on a
# value where the guarded action is already idempotent. Clamping x to L when x
# already equals L, slicing a string to its own length, truncating a slice to
# its current length. No observable output differs, so no test can kill it.
#
# Raising an entry is a normal part of adding tests. Lowering one needs a
# reason in the commit message.
