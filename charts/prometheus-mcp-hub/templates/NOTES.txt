WARNING - ingress.enabled=false, so nothing outside this cluster can reach this hub.
  Since ADR-0014 the spoke tunnel is a WebSocket on the MCP listener, published by
  the SAME standard Ingress as the MCP endpoint. There is no tunnel Service, no

{{- if .Values.ingress.enabled }}

IDLE TIMEOUTS
  The tunnel is a long-lived WebSocket through your Ingress controller. Its HTTP/2
  keepalive pings run every 10s, comfortably inside nginx's 60s proxy-read-timeout
  default, so defaults are fine. A controller configured BELOW that will drop every
  spoke in the fleet on a timer. On ingress-nginx, raise it with
    nginx.ingress.kubernetes.io/proxy-read-timeout: "3600"
  set through ingress.annotations.
{{- end }}

{{- if gt (int .Values.replicaCount) 1 }}

replicaCount={{ .Values.replicaCount }}. Read this before relying on it:
  A spoke tunnel is pinned to ONE hub replica and there is deliberately no
  hub-to-hub forwarding. Credential state is shared (it is one Secret), but tunnels
  are not. Every replica must be individually routable from outside the cluster and
  every spoke must list all {{ .Values.replicaCount }} URLs in hub.endpoints. Putting several replicas
  behind one Service does NOT give you HA; it gives you a fleet where each cluster
  is visible to exactly one replica. Per-replica addressing is now ordinary HTTP
  routing - a hostname or a path prefix per replica on the same Ingress.
{{- end }}

  Every admin call needs an admin bearer token. The hub printed one ONCE on first
  start; capture it before it scrolls away:
       kubectl -n {{ $ns }} logs deploy/{{ $deploy }} | grep pmf_adm_
{{- if not .Values.adminToken.existingSecret }}
  Put it in a Secret and mount it, so the commands below can read it from a file
  instead of carrying it in the node's process table:
       kubectl -n {{ $ns }} create secret generic pmf-admin --from-literal=admin-token='pmf_adm_...'
       helm upgrade {{ .Release.Name }} <chart> -n {{ $ns }} --reuse-values --set adminToken.existingSecret=pmf-admin
  Until then, append --admin-token-file <file> to each command below (or set
  PMF_ADMIN_TOKEN in the exec's environment).
{{- end }}
  1. Mint an agent key:
       kubectl -n {{ $ns }} exec deploy/{{ $deploy }} -- \
         hub keys create --class agent --name <bot-name> --clusters '*' --tools '*'{{ $tokenFlag }}{{ $adminURL }}
  2. Mint an enrollment token per cluster:
       kubectl -n {{ $ns }} exec deploy/{{ $deploy }} -- \
         hub enroll create --cluster <cluster-id>{{ $tokenFlag }}{{ $adminURL }}
     then install prometheus-mcp-spoke in that cluster with
       cluster.id=<cluster-id>
       enrollment.token=<the pmf_enr_ token>   (or enrollment.existingSecret)
       hub.endpoints[0]={{ if .Values.ingress.enabled }}wss://{{ .Values.ingress.host }}{{ .Values.tunnel.path }}{{ else }}wss://<external hub host>{{ .Values.tunnel.path }}{{ end }}
       hub.apiUrl={{ with (include "prometheus-mcp-hub.publicOrigin" .) }}{{ . }}{{ else }}https://<external hub host>{{ end }}
     hub.apiUrl is scheme and host ONLY: the spoke appends /enroll itself, so the
     MCP URL ({{ include "prometheus-mcp-hub.publicURL" . }}) would make it POST to /mcp/enroll and fail.
     Leave hub.caBundle empty when the Ingress serves a publicly trusted certificate.
     For a private issuer, hub.caBundle is THAT issuer's CA (the one that signed the
     Ingress certificate), never this hub's /pki/bundle, which signs spoke identities
     and vouches for no server.
  3. Watch spokes attach:
       kubectl -n {{ include "prometheus-mcp-hub.namespace" . }} logs deploy/{{ include "prometheus-mcp-hub.fullname" . }} -f
