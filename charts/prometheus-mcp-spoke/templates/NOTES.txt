If the spoke cannot reach the hub
  This is the usual first-install failure, and it is almost always a network or DNS
  problem in THIS cluster, on the outbound path. The hub never dials in, so there is
  nothing to fix on the hub's firewall. Work down this list:

  1. The pod stays Running but NotReady, and the log repeats a dial error. That is
     correct behaviour: /healthz never checks a dependency, so an unreachable hub must
     not restart the pod.
  2. DNS. Resolve the hub name from inside this cluster:
       kubectl -n {{ include "prometheus-mcp-spoke.namespace" . }} exec deploy/{{ include "prometheus-mcp-spoke.fullname" . }} -- nslookup {{ if .Values.hub.endpoints }}{{ include "prometheus-mcp-spoke.endpointHost" (first .Values.hub.endpoints) }}{{ else }}<hub host>{{ end }}
     (the spoke image is distroless, so run this from a debug pod if exec has no shell).
  3. Egress. {{ if .Values.networkPolicy.enabled }}This release rendered a NetworkPolicy. Its hub rule is an ipBlock, because
     the hub is not in this cluster and cannot be selected by namespace. Confirm the
     hub's real address falls inside networkPolicy.egress.hub.cidrs
     ({{ join ", " .Values.networkPolicy.egress.hub.cidrs }}), and that {{ range $i, $e := .Values.hub.endpoints }}{{ if $i }}, {{ end }}port {{ include "prometheus-mcp-spoke.endpointPort" $e }}{{ end }} is allowed.
     Also check any OTHER NetworkPolicy in this namespace: policies are additive only
     for allow, and a default-deny egress policy elsewhere still applies.{{ else }}networkPolicy.enabled=false here, so check for a cluster-wide default-deny
     egress policy, a service mesh sidecar, or an egress gateway in front of you.{{ end }}
  4. Corporate proxy or egress NAT. The tunnel is raw mTLS over TCP, NOT HTTP, so an
     HTTP forward proxy cannot carry it and HTTPS_PROXY is not consulted. It needs a
     real TCP path to {{ join ", " .Values.hub.endpoints }}.
  5. TLS. "certificate signed by unknown authority" means the trust bundle is wrong:
     set hub.caBundle or hub.existingCASecret. "certificate is valid for X, not Y"
     means the hub's tunnel.serverNames does not list the address you put in
     hub.endpoints -- that is fixed on the hub, not here.
  6. Enrollment 401/409. A single-use token that was already redeemed returns a replay
     error; mint a fresh one. In identity.backend=memory every restart redeems again,
     which is why that mode needs a multi-use token.
